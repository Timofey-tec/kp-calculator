# Калькулятор КП с автогенерацией договора

Pet-проект, воссоздающий реальный кейс из практики: калькулятор коммерческого
предложения для B2B (завод/застройщик/курорт), который сокращает время
подготовки КП с ~2 часов до ~20 минут — сумма пересчитывается в реальном
времени, а по нажатию кнопки сразу формируется договор в .docx со сметой,
подставленной из формы.

Ключевая фича — механика **«бесплатной» доставки**: если менеджер включает
опцию «доставка бесплатно», её стоимость не появляется в смете отдельной
строкой, а прозрачно для клиента размазывается по остальным позициям сметы
пропорционально их доле в общей сумме.

## Стек

- **Фронтенд:** React + TypeScript + Vite + Tailwind CSS. Состояние формы —
  `useReducer` с типизированными экшенами. Бизнес-логика расчёта (в т.ч.
  распределение доставки) вынесена в чистые функции, не зависящие от UI.
- **Бэкенд:** Python 3.12, FastAPI, `python-docx` (генерация договора без
  шаблонизаторов — плейсхолдеры и таблица собираются напрямую через
  OOXML-дерево), Pydantic, SQLAlchemy + SQLite (история КП), `num2words`
  (сумма прописью).

## Структура репозитория

```
calculator/
├── frontend/                    # React + TS + Vite + Tailwind
│   └── src/
│       ├── types/quote.ts               — общие типы
│       ├── logic/quoteCalculations.ts   — чистая бизнес-логика (+ тесты)
│       ├── state/quoteReducer.ts        — useReducer с типизированными экшенами (+ тесты)
│       ├── api/client.ts                — обёртки над backend API
│       ├── data/sampleQuote.ts          — демо-данные ("Загрузить пример")
│       └── components/                  — UI-компоненты
└── backend/                     # FastAPI
    ├── app/
    │   ├── main.py                      — приложение, CORS, роуты
    │   ├── schemas.py                   — Pydantic-модели (зеркало frontend/types)
    │   ├── services/
    │   │   ├── calculations.py          — та же бизнес-логика на Python (+ тесты)
    │   │   ├── number_to_words.py       — сумма прописью
    │   │   └── docx_generator.py        — сборка договора из шаблона
    │   ├── routers/                     — /api/calculate, /api/contract/generate, /api/quotes
    │   └── templates/contract_template.docx — шаблон договора (коммитится в репозиторий)
    ├── scripts/build_template.py        — скрипт, которым собран шаблон (для правок текста)
    └── tests/                           — pytest
```

## Как запустить

### Бэкенд

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload    # http://localhost:8000
```

При первом запуске автоматически создаётся `app/data.db` (SQLite) для
истории КП.

### Фронтенд

```bash
cd frontend
npm install
npm run dev                      # http://localhost:5173
```

Фронтенд по умолчанию обращается к `http://localhost:8000`; при
необходимости адрес можно переопределить переменной окружения
`VITE_API_BASE_URL`.

Демо можно запустить сразу после клонирования: шаблон договора уже собран
(`backend/app/templates/contract_template.docx`), а кнопка «Загрузить
пример» на фронтенде подставляет тестовую смету.

### Тесты

```bash
# бэкенд
cd backend && source .venv/bin/activate && pytest

# фронтенд (чистая бизнес-логика и reducer)
cd frontend && npm run test
```

## Как устроена бизнес-логика (для собеседования)

- **Расчёт сметы и распределение доставки** — `frontend/src/logic/quoteCalculations.ts`
  и его 1:1 портированный аналог `backend/app/services/calculations.py`.
  Это чистые функции без побочных эффектов и без зависимостей от React/FastAPI:
  фронтенд использует их для мгновенного пересчёта на каждое изменение формы,
  бэкенд — для независимой серверной валидации через `POST /api/calculate`.
  Оба модуля покрыты тестами с одинаковыми кейсами (базовые суммы, скидки,
  НДС, платная/бесплатная доставка, edge case нулевой сметы).
- **Генерация договора** — `backend/app/services/docx_generator.py`. Без
  шаблонизаторов (jinja/docxtpl): открывается заранее собранный
  `contract_template.docx`, скалярные плейсхолдеры вида `{{COMPANY_NAME}}`
  заменяются по тексту параграфов, а таблица сметы вставляется в OOXML-дерево
  документа на место параграфа-маркера `{{SMETA_TABLE}}` (`paragraph._p.addnext(table._tbl)`).

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/calculate` | Серверный пересчёт сметы (независимая валидация) |
| POST | `/api/contract/generate` | Генерация .docx, сохранение в историю, отдача файла |
| GET | `/api/quotes` | Список сформированных КП |
| GET | `/api/quotes/{id}/download` | Повторное скачивание ранее сгенерированного договора |
| GET | `/api/health` | health-check |

## Что можно улучшить дальше

- Несколько шаблонов договора (под разные типы сделок/юрлиц) с выбором в UI.
- Экспорт КП в PDF (превью перед скачиванием .docx).
- Роли пользователей (менеджер / администратор шаблонов) и аутентификация.
- Docker-compose для запуска обеих частей одной командой.
- E2E-тесты (Playwright) поверх реального сценария «заполнил смету → скачал договор».
- Мультивалютность и настраиваемые ставки налога помимо НДС.
