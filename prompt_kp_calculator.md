# Промпт для Claude Code: Калькулятор КП с автогенерацией договора

## Контекст задачи

Собери мне pet-проект для собеседования/стажировки. Целевая компания занимается заказной веб-разработкой (Laravel + Vue) для застройщиков, заводов, курортов — и делала для одного из клиентов (завод) похожую систему: калькулятор коммерческого предложения, который сократил время расчёта КП с 2 часов до 20 минут, автоматически подставляет смету в шаблон договора и умеет размазывать стоимость "бесплатной" доставки по остальным позициям сметы (скрытые позиции).

Мой стек: React + TypeScript на фронтенде, Python на бэкенде (FastAPI). Хочу сделать компактную, но полноценно работающую версию этого кейса — с реальным демо, а не моком.

## Функциональные требования

### 1. Калькулятор сметы (фронтенд)

- Форма с динамическими строками позиций сметы: наименование, количество, цена за единицу, скидка (%).
- Позиции можно добавлять и удалять.
- Итоговая сумма пересчитывается в реальном времени при любом изменении.
- Поддержка НДС (вкл./выкл., ставка настраивается, по умолчанию 20%).
- Поле "Доставка": если включена опция "сделать доставку бесплатной", её стоимость не показывается отдельной строкой, а равномерно распределяется по остальным позициям сметы (наценка на каждую позицию пропорционально её доле в общей сумме). Реализуй именно этот механизм — это ключевая фича, отсылающая к реальному кейсу.
- Валидация: количество и цена не могут быть отрицательными, обязательно хотя бы одна позиция сметы.
- Блок с данными клиента: название компании, ИНН (опционально), контактное лицо, телефон/email.

### 2. Генерация договора (бэкенд)

- Бэкенд на FastAPI принимает JSON со сметой и данными клиента.
- Генерирует .docx-документ по заранее подготовленному шаблону договора с помощью `python-docx`.
- В документ подставляется:
  - Данные клиента (шапка договора)
  - Таблица сметы: позиция / количество / цена / скидка / сумма
  - Итоговая сумма прописью и цифрами
  - Дата формирования документа
- Endpoint возвращает готовый файл для скачивания (StreamingResponse / FileResponse).
- Добавь endpoint для просто пересчёта суммы на бэкенде (на случай, если понадобится валидация серверной стороной, независимая от фронта).

### 3. История КП (опционально, если останется время)

- Простое сохранение сформированных КП (SQLite через SQLAlchemy).
- Список ранее сформированных КП с возможностью скачать файл повторно.

## Технические требования

- **Фронтенд:** React + TypeScript + Vite + Tailwind CSS. Управление состоянием формы — через `useReducer` с чёткой типизацией экшенов (аналогично тому, как я делал в kanban-доске). Логика расчётов (в т.ч. распределение стоимости доставки) должна быть вынесена в отдельные чистые функции/модуль, полностью отделённые от UI-компонентов — их нужно уметь протестировать независимо.
- **Бэкенд:** Python 3.11+, FastAPI, python-docx, Pydantic-модели для валидации входных данных, uvicorn для запуска.
- **Структура репозитория:** монорепо с папками `frontend/` и `backend/`, README с инструкцией по запуску обеих частей.
- Настрой CORS на бэкенде для локальной разработки с фронтендом.
- Не используй localStorage для критичных данных на бэкенд-части (это относится только к фронту, если история КП не подключена к БД).

## Дизайн / UX

- Минималистичный, деловой интерфейс — это B2B-инструмент для менеджера, а не консьюмерский продукт. Обращайся к дизайн-гайду проекта, если он есть в окружении (frontend-design skill), для выбора шрифтов и цветовой палитры — избегай шаблонного вида "дефолтный Tailwind".
- Таблица сметы должна быть удобной для быстрого ввода данных (табличная навигация Tab/Enter между полями — плюс, но не обязательно).
- После генерации договора — явный визуальный фидбек (успех/ошибка), а не просто скачивание файла в тишине.
